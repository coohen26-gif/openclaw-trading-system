## **1️⃣ BUG #1 : Positions "CLOSED" sans PnL calculé** 🔴 CRITIQUE

### **Symptôme**
3 signaux ont le statut `CLOSED` mais **aucune entrée dans la table `positions`** :

```sql
SELECT id, timestamp, pair, status FROM signals WHERE status = 'CLOSED';
-- Résultat :
-- 1 | 2026-05-16T02:15:00 | ETHUSDT | CLOSED
-- 2 | 2026-05-16T14:30:00 | BTCUSDT | CLOSED
-- 3 | 2026-05-17T03:45:00 | BTCUSDT | CLOSED

SELECT * FROM positions WHERE signal_id IN (1,2,3);
-- Résultat : (vide) ❌
```

### **Cause Racine**
Ces 3 signaux ont été **migrés manuellement** depuis les rapports historiques avec le statut `CLOSED` au lieu de `OPEN`.

La fonction `update_position()` **ne s'exécute pas** si `current_status != "OPEN"` :

```python
if current_status != "OPEN":
    conn.close()
    return {"status": "already_closed", "outcome": current_status}  # ❌ Sortie sans calculer PnL
```

### **Impact**
- **Win Rate faux** : Devrait inclure ces 3 trades (si TP/SL vérifiés)
- **PnL total faux** : +5 899 USDT actuel → devrait être plus élevé
- **Dashboard incomplet** : 3 trades manquants dans les stats

### **Solution**
```python
# Option 1 : Changer statut CLOSED → OPEN pour re-migration
UPDATE signals SET status = 'OPEN' WHERE id IN (1,2,3);
-- Puis relancer update_position() avec prix actuels

# Option 2 : Créer fonction migrate_closed_position()
def migrate_closed_position(signal_id, exit_price, exit_time):
    # Insère directement dans positions sans check TP/SL
    pass
```

### **Fix Immédiat**

## **3️⃣ BUG #3 : PnL Calculé Faux (Formule Erronée)** 🟠 MAJEUR

### **Symptôme**
Dans `update_position()` :

```python
# Ligne 174-177
pnl_percent = ((exit_price - entry_price) / entry_price) * 100
pnl_usdt = pnl_percent * entry_price / 100  # ❌ FORMULE FAUSSE
```

**Exemple avec BTCUSDT #1 :**
- Entry : 76 832
- Exit : 78 828
- PnL % : ((78 828 - 76 832) / 76 832) × 100 = **2.60%** ✅
- PnL USDT : 2.60 × 76 832 / 100 = **1 997.63** ❌ (devrait être ~1 996)

**Le dashboard affiche +1 996 USDT** → Proche, mais **formule incorrecte**.

### **Cause Racine**
Formule correcte :
```python
# Pour LONG :
pnl_usdt = (exit_price - entry_price)  # Difference directe (1 unit)
# OU avec position size :
pnl_usdt = (exit_price - entry_price) * position_size
```

Formule actuelle (fausse) :
```python
pnl_usdt = pnl_percent * entry_price / 100
# = (((exit - entry) / entry) * 100) * entry / 100
# = (exit - entry) * (100/100) * (entry/entry)
# = exit - entry  # ✅ Tombe juste par accident pour 1 unit
```

**La formule est techniquement correcte pour 1 unit**, mais **confusante** et **fausse pour position_size > 1**.

### **Impact**
- **Actuel** : Correct pour 1 unit (chance)
- **Futur** : Faux si position_size ≠ 1

### **Solution**
```python
# Corriger formule (clair et correct pour tout position_size)
position_size = 1.0  # 1 unit par défaut
if direction == "LONG":
    pnl_usdt = (exit_price - entry_price) * position_size
else:
    pnl_usdt = (entry_price - exit_price) * position_size
pnl_percent = (pnl_usdt / entry_price) * 100
```

## **4️⃣ WARNING #1 : Pas de Circuit Breaker** 🟠 MOYEN

### **Symptôme**
Aucune limite de drawdown implémentée.

### **Risque**
Si 5-10 trades perdants consécutifs → Drawdown >20% → Système continue à trader.

### **Solution**
```python
# Dans tracker.py
MAX_DRAWDOWN = 0.15  # 15%
MAX_LOSS_STREAK = 5

def check_circuit_breaker():
    stats = get_performance()
    if stats['losses'] >= MAX_LOSS_STREAK:
        return "COOLDOWN_24H"
    if stats['total_pnl_usdt'] < -MAX_DRAWDOWN * 10000:  # 10k capital
        return "COOLDOWN_72H"
    return "OK"
```
